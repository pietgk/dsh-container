Implementation proposal based on dsh-container-plan.md, handoff v2
Recommended execution order

Prove the boundary, then build the manager.

The first production code should appear only after one exact DSH image can run securely and its Web UI can cross the guest loopback boundary without becoming reachable on a guest interface.

The dependency path

This is the shortest sequence that keeps every later result tied to the exact runtime we intend to ship.

flowchart TD
  R["0. Read-only revalidation\nHost, DSH SHA, Apple docs, Colima snapshot"] --> P["1. Apple prerequisite qualification\nInstall only after approval, prove runtime controls"]
  P --> C["2. Freeze Phase 0 fixture\nExact SHA, resource names, ports, assertions"]
  C --> B["3. Spike B first\nImmutable Linux arm64 image and runtime closure"]
  B --> A["4. Spike A with Spike B image\nGuest loopback to Unix socket to Mac loopback"]
  A --> G{"5. Architecture gate\nBoth proofs pass?"}
  G -- "No" --> X["Stop and amend architecture\nNo manager skeleton"]
  G -- "Yes" --> S["6. Manager foundations\nMetadata, journal, adapter, reconciler, dry-run"]
  S --> V["7. Apple vertical slice\nstatus, init, start, logs, stop, delete"]
  V --> H["8. Lifecycle and security acceptance\nFailure injection, drift, exact cleanup, browser E2E"]
  H --> E["9. Evaluation\nHost-native baseline and container scenarios"]

The handoff names Spike A before Spike B, but does not require that execution order. Reusing the exact Spike B image in Spike A removes a major source of test drift.

Implementation sequence

Each stage has an evidence-based exit condition. Passing a command is not enough when a functional check is available.

00

Revalidate without changing the host

Capture the current host and source facts, resolve the candidate DSH release to a full official SHA, and convert every dated assumption into a checked item.

  • Host architecture, macOS, Node, pnpm, Zed, Apple Container, and Colima.
  • DSH build graph, Web flags, state paths, telemetry control, provider setup, and shutdown timeout.
  • Snapshot the existing Colima default state and configuration so later acceptance can prove it was untouched.
Exit evidence

A dated assumption matrix with command or source references, plus one selected immutable DSH SHA.

01

Qualify the Apple prerequisite

After explicit installation approval, verify the exact installed Apple Container version and run tiny disposable probes before involving DSH.

  • Prove read-only rootfs, tmpfs, capability drop, CPU, memory, nproc, and nofile behavior.
  • Prove named volumes, non-root ownership, dedicated networking, socket publication, and exact cleanup.
  • Use deterministic spike names and preserve command output. Never touch Colima.
Exit evidence

The installed runtime can enforce every version 1 control required by the plan, or the architecture stops here.

02

Freeze the Phase 0 fixture

Create a small spike-only area, not the manager project. Lock exact names, paths, image inputs, guest and host ports, commands, expected positives, and expected negatives.

  • Keep scripts rerunnable and cleanup target lists explicit.
  • Define the browser scenarios before testing the bridge.
  • Record deviations in one short Phase 0 report.
Exit evidence

Another developer can reproduce or clean up the spikes without guessing any target.

03

Spike B: build the exact image

Build from git archive <sha> in a clean multi-stage Linux arm64 build. Compile the static-musl launcher and construct a minimal runtime closure.

  • Pin the Node base by digest, honor the repository pnpm version, and use the frozen lockfile.
  • Run and record the production dependency audit gate.
  • Prove non-root execution with only /workspace, /state, /cache, and /tmp writable.
  • Prove frontend serving, constrained shell execution, session persistence, Landlock usability, and graceful exit.
Exit evidence

Image digest, full provenance record, audit result, writable-path proof, runtime inventory, and a clean DSH Web startup.

04

Spike A: prove the Web path with that image

Keep DSH on guest 127.0.0.1. Bridge it to an owner-only guest Unix socket, publish that socket, then proxy it from a manager-owned Mac loopback listener.

  • Exercise page load, API calls, streaming, reconnect, readiness, trusted-host rejection, and graceful shutdown.
  • Use browser E2E against the Mac URL and inspect representative viewport screenshots.
  • Enumerate every guest vmnet IPv4 and IPv6 address and prove direct access fails.
  • Inspect Mac listeners and prove no non-loopback listener exists.
Exit evidence

Functional Web evidence plus negative reachability evidence. Any guest-interface listener or broad DSH bind is a failure.

05

Hold the architecture gate

Review both spike records as a single system. Resolve contradictions before any abstraction makes them harder to see.

  • Pass only when the exact image and exact transport work together.
  • Record accepted limitations, especially unrestricted egress and the local macOS user threat-model boundary.
  • If a spike fails, compare Apple redesign, an authenticated boundary, or a reviewed Colima promotion.
Exit evidence

A written go decision with no weakened invariant. A no-go decision ends implementation work.

06

Build manager foundations

Now create the TypeScript project. Start with ownership, reconciliation, and diagnosability rather than command-specific happy paths.

  • Versioned schemas, atomic metadata writes, per-instance operation lock, deterministic names, and stable internal IDs.
  • Structured process execution, secret-safe logs, dry-run, exact-target display, and typed errors.
  • Partial-failure journal and a lifecycle state machine that reconciles expected and observed Apple resources.
  • Apple command construction behind a product-operation adapter, with no fake second-backend parity.
Exit evidence

Unit-tested foundations can model absent, stopped, ready, drifted, partially created, and failed instances without real mutations.

07

Deliver the Apple vertical slice in dependency order

Implement the user journey as thin end-to-end increments. Keep security controls and cleanup semantics inside each increment.

  • status and host probe first, because every mutating command needs reconciliation.
  • init next: source selection, audit, image reuse/build, acknowledgements, metadata, volumes, workspace, and network.
  • start with the proven supervisor and bridge, then logs, stop, default delete, and explicit destructive deletes.
Exit evidence

One named bind-mode instance completes the full lifecycle twice, preserving state and workspace and removing only exact owned runtime targets.

08

Break it before evaluating it

Run the lifecycle, security, failure, and UI suites on the exact Apple runtime. Inject recoverable partial states rather than testing only clean starts.

  • Port conflicts, stale PIDs, missing sockets, missing containers, drifted resources, readiness timeout, forced shutdown, and interrupted initialization.
  • Credential isolation, sibling-workspace denial, read-only root, functional resource ceilings, direct-IP denial, and exact destructive cleanup.
  • Browser behavior, streaming, reconnect, and representative viewport visual checks.
Exit evidence

All acceptance criteria pass repeatedly, logs contain no configured secrets, and the Colima default profile remains unchanged.

09

Run the actual DSH evaluation

Only after the isolation product is stable should its overhead and DSH usefulness be measured.

  • Run the same trusted scenario host-native and containerized.
  • Separate guest DSH process metrics, Apple VM host metrics, and end-to-end timings.
  • Exercise plugin discovery, constrained code changes, resumed sessions, package installation, builds, tests, language tooling, trajectory, tokens, and Web UX.
Exit evidence

A concise evaluation report that can support a decision on volume workspaces, offline enforcement, Colima, or E2B.

Vertical-slice command order

The public CLI contract stays unchanged. This is the internal build order that reduces hidden coupling.

1. statusObserve before mutating

Build host probing, metadata reading, backend inspection, health, drift, and redaction first.

2. initCreate reproducibly

Add immutable source selection, audit policy, image identity, acknowledgements, and exact owned resources.

3. startReconcile into ready

Apply mounts and controls, start the container and proxy, wait through the public URL, then rerun exposure checks.

4. logsMake failure diagnosable

Expose bounded and follow views for DSH, proxy, and lifecycle logs with tested secret redaction.

5. stopProve controlled shutdown

Honor DSH disposal timing, distinguish graceful from forced termination, and remove ephemeral bridge resources exactly.

6. deleteSeparate every blast radius

Default to container-only deletion. Resolve, display, confirm, and independently test state, cache, workspace, network, and image deletion.

First approval we will need

Apple Container is absent on the current host snapshot. Revalidation is read-only, but installation is a separate host mutation and should be approved only when we are ready to run Phase 0.

What we should not start yet

  • No package.json for the manager.
  • No Colima fallback or second backend abstraction.
  • No volume workspace or offline-policy work.
  • No modifications to the DSH checkout.
